# Contributing

Help make finance workflows clearer, more reproducible, and easier to review.

## Propose an improvement

Open a [GitHub issue](https://github.com/Xiaowen-CHEN-Learner/AI-for-Finance-Department/issues) describing the business problem, affected workflow, expected result, and evidence. Include the workflow version and a minimal synthetic example where possible.

Use fictional or properly anonymized data. Public issues, pull requests, and examples should not contain client records, credentials, tax identifiers, bank details, or confidential board material.

## Prepare a pull request

1. Explain the problem and intended behavior before changing the workflow.
2. Keep the change focused. Preserve existing paths or update all affected links when a move is necessary.
3. Update relevant documentation, examples, and internal version history when behavior changes.
4. Check local links and any calculations or output schemas touched by the change.
5. State what you verified and what still requires tool execution or professional review.

## Workflow quality

A useful workflow makes its purpose, boundaries, inputs, outputs, steps, assumptions, validation rules, exceptions, and reviewer handoff explicit.

- Use exact source references for financial facts and date-sensitive requirements.
- Separate accounting basis, tax treatment, business assumptions, and implementation choices.
- Preserve source traceability and quantify excluded or unresolved items where possible.
- Label example data as synthetic and provide reproducible expected results.
- Describe observed checks accurately; do not infer client acceptance from passing arithmetic.

Use the [catalog](Version_2/README.md), [engagement brief](templates/ENGAGEMENT_BRIEF.md), and [review record](templates/REVIEW_RECORD.md) to keep navigation and handoffs consistent.

## Scope of public contributions

The repository contains workflow specifications and examples. Do not claim a live integration, completed professional review, performance improvement, or supported deployment without corresponding evidence.

Licensing terms remain a maintainer decision. Include third-party material only when authorized.
